### Pertanyaan Reflektif

> 1. Pada Tutorial dan Tugas 1, Anda diberi kebebasan untuk menentukan tampilan dari website portofolio Anda. Saat Anda merancang struktur HTML yang digunakan, apakah Anda menggunakan elemen semantik HTML5 seperti '<section>', <article>, atau <aside>? Jika iya, bagaimana elemen tersebut membantu Anda dalam membuat static web? Jika tidak, mengapa tanpa elemen tersebut sudah memenuhi kebutuhan desain Anda?

**Ya**, saya menggunakan beberapa semantik HTML5, seperti `<section>` dan `<article>`. Tag `<section>` banyak saya gunakan untuk membagi halaman saya menjadi beberapa bagian/tema, seperti About, Skills, Projects, Experiences. Tag `<article>` saya gunakan untuk mengelompokkan beberapa item/konten yang berdiri sendiri, dalam kode saya, saya menerapkannya untuk setiap item pada bagian Projects dan Experiences.

Menggunakan elemen-elemen tersebut membantu saya mengorganisir struktur HTML sehingga saya lebih mudah dalam memahami isi kode saya. Selain itu, hal tersebut juga membantu saya dalam mendesain bagian bagian tertentu dengan CSS. Tak hanya itu, menerapkan semantik HTML yang baik membantu meningkatkan aksesibilitas dan mengoptimalkan SEO (_Search engine Optimization_).

> 2. Ketika Anda mengatur CSS Anda agar tetap responsive, tantangan tata letak apa yang Anda temukan? Bagaimana Anda mengevaluasi elemen mana yang harus diubah posisinya atau diprioritaskan ukurannya saat berpindah dari tampilan desktop ke mobile?

Salah satu tantangan terbesar saya sebagai seorang yang baru belajar mendesain web adalah menerapkan _navigation bar_ untuk mobile. Pada tampilan desktop, _navigation bar_ hanya cukup memanjang ke samping dan itu tidaklah menjadi sebuah masalah. Namun, ketika dijalankan diperangkat mobile, bagian _navigation bar_-nya terpotong dan memanjang ke samping. Tentu ini akan jadi pengalaman yang buruk bagi pengguna jika seseorang mencoba mengakses website lewat perangkat mobile.

Untuk mengatasinya, saya mencoba melihat beberapa website portofolio milik orang lain, dan saya dapatkan salah satu caranya adalah menggunakan apa yang disebut dengan **Humberger Menu** yang menggantikan bagian _navigation bar_ untuk perangkat mobile. Saya menggunakan JavaScript agar tombol dapat ditutup dan dibuka serta dapat berubah menjadi ikon **x** ketika menu sedang dibuka.


> 3. Website yang Anda buat saat ini adalah static web murni. Batasan apa yang Anda rasakan saat mencoba menyajikan informasi pada portofolio Anda secara optimal? Berdasarkan batasan tersebut, fungsionalitas dinamis apa yang paling ingin Anda persiapkan dan tambahkan pada iterasi proyek selanjutnya?

Karena masih berupa _static web_, banyak informasi di dalam website masih berupa statis. Sehingga, jika ada pembaruan, maka harus diperbarui secara manual di kode HTML. Namun, jika hanya sebatas website portofolio sederhana, saya rasa hal ini sudah sangat cukup. Untuk _fungsionalitas dinamis_-nya mungkin saya rasa fitur **Contact Form** cukup menarik, tapi entahlah, hehe :).
